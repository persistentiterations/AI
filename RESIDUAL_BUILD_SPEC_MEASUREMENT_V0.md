# RESIDUAL_BUILD_SPEC_MEASUREMENT_V0

Status: bounded measurement experiment (read-only, no code changed). Machine-readable
evidence: `RESIDUAL_BUILD_SPEC_MEASUREMENT_MACHINE.json` (24 seeds). Generated by
`baby_ai/assays/residual_build_spec_measurement.py`.

## 1. Purpose and model

Question: *given the fixed FormationCore evaluator, how much per-instance state must be
carried to regenerate the correct admissibility result?*

Regeneration model: one per-instance residual is captured once at the end of the
program (the state that would be persisted between runs); the FIXED evaluator then
regenerates each query verdict. Fixtures: R8 (acyclic-independent testbed with the
cycle + RELIEVE), 24 frozen seeds. Every query must be reproduced, including at-prefix
queries (`a_in_cycle`, `b_in_cycle` at `at=3`) whose correct verdict is the state
BEFORE the RELIEVE op.

## 2. Candidates compared

| candidate | contents | how it regenerates |
|---|---|---|
| A | exhaustive derived admissibility snapshot: per-query `{decision, causes}` table | direct lookup |
| B | formed state (subject→group) + full dependency ledger (event history) | replay FORM events, replay DEPEND/RELIEVE ledger events up to the query `at` prefix, fixed-evaluator route |
| C | formed state + CURRENT dependencies map only (no event history) | replay FORM events, apply current deps unconditionally, fixed-evaluator route |

Shared-evaluator cost (the recursive-admissibility walk + topology semantics) is
counted separately as 1 unit per candidate; the per-instance residual is what the size /
fact columns measure.

## 3. Results (24 seeds)

| metric | A | B | C |
|---|---|---|---|
| reconstructs ALL queries on ALL seeds | yes | yes | **no** |
| serialized size (bytes), min..max | 366..374 | 392..422 | 125..139 |
| explicit facts, min..max | 17..17 | 16..16 | 6..6 |

C fails on exactly `a_in_cycle` and `b_in_cycle` on every seed: it PROCEEDs where the
oracle HOLDs. Cause: the end-of-program residual reflects the RELIEVE already applied
(`b` unbound), and C has no history with which to restore the pre-RELIEVE dependency
topology; the query is genuinely answerable only from the EARLIER causal state.

B reproduces the cycle HOLD with the exact oracle cause strings
(`prerequisite_missing:<direct prereq>`) on all seeds and all at-prefix queries, because
the ledger carries the ordered DEPEND/RELIEVE events that the replay truncates at the
query prefix. A reproduces everything trivially since it embeds the verdicts directly.

Rewinding with C (apply-edits only from current map) can also reproduce a later redeclare
DEPEND → RELIEVE mutation identically to the oracle (`mutate_agrees_oracle: true` on all
seeds), but this does not repair C's at-prefix failure.

## 4. Conclusion

- **B is a viable candidate residual build specification**: local formed state + full
  dependency ledger, replayed under the fixed evaluator, regenerates every correct
  admissibility result including at-prefix cycle HOLDs and exact cause strings.
- **A offers no compression over B** for the regeneration task; B is the leaner
  representation that still supports correct regeneration.
- **C is NOT a valid residual specification** for this fixture class: history-free
  current-state alone cannot reproduce queries that depend on an earlier causal point
  (the pre-RELIEVE cycle). This is direct evidence that formation *event history*
  matters beyond current-state morphology for at-prefix queries — see the parallel
  finding in R9 notes / `FORMATIONCORE_FABULOUS_FIVE_CROSSWALK_V0.md`.
- **NO_MEANINGFUL_RESIDUAL_COMPRESSION beyond B is established**: no smaller defensible
  representation (C) reproduces the full query set, so within this testbed the ledger
  is not wasteful; C's size win is bought by losing correctness. (A second independent
  CB-... check: comparing sizes A≈B shows the admissibility outcome is essentially data,
  i.e. no hidden evaluator trick beyond the shared walk.)

## 5. Accounting statement

Per-instance residual state: B = formed subjects + ledger events (16 facts, ~400 bytes
max on this fixture). Shared evaluator cost: 1 unit (route walk with recursive
admissibility). Claimed interdependency: the ledger is required because at-prefix
regeneration needs event history; the evaluator alone cannot derive the earlier state
from current-deps-only.

## 6. Boundary

This measures the R8 testbed (two-node cycle + RELIEVE). It is not a claim about R9
(temporal) state, cross-domain transfer, or "minimality" outside this fixture shape.
It does NOT claim the ledger is the global minimum residual build specification; it
establishes that within what is measurable here, C (the candidate smaller
representation) fails correctness, supporting the honest outcome
`NO_MEANINGFUL_RESIDUAL_COMPRESSION` rather than asserting a minimum.
